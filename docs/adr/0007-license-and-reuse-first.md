# ADR-0007：项目许可证 MPL-2.0，复用优先

- 状态：已采纳
- 日期：2026-11-19
- 相关需求：REQUIREMENTS 第 5 节"合规红线"

## 背景

之前的规则是"不复制 AGPL 代码，GPL/AGPL 一律不进核心"，但没有定项目自己的许可证，也没有鼓励复用的规则。结果是能直接拿来用的成熟代码（例如 MPL-2.0 的 Finamp、MIT 的 beets）也没有用上，很多东西是从零写的。

已经确定的产品决策：

- 商业模式：开源 + 可选的付费 Pro 版
- 要上应用商店（App Store、Google Play、微软商店）

这两条决定了项目许可证不能选 GPL/AGPL：GPL 和 App Store 的条款冲突（VLC 2011 年因此被下架过），也做不了闭源的 Pro 功能。

## 决策

### 1. 项目许可证：MPL-2.0

核心（`core/`）和 Flutter 客户端（`app/`）都用 **MPL-2.0**。

- MPL 是**文件级** copyleft：改了 MPL 文件就要公开这些文件；新写的闭源文件可以和它一起分发。
- 所以 Pro 功能放在单独的私有仓库，以独立模块或插件的形式接入，不改开源文件。
- 能上应用商店。
- 能直接复用 MPL-2.0 的代码（Symphonia、Finamp 都是 MPL-2.0）。

### 2. 复用优先

**写一个新模块之前，先查 [docs/REUSE.md](../REUSE.md) 和市面上的现成方案。** 能用现成的库就用库，能拷代码就拷代码，都不行再自己写。自己写的话，在 PR 里说一句为什么不用现成的。

### 3. 按许可证分四档

| 档位 | 许可证 | 能怎么用 |
|---|---|---|
| ✅ **直接用** | MIT、Apache-2.0、BSD、ISC、Zlib、MPL-2.0、CC0、Unlicense | 作为依赖引入，或者**直接拷代码**。拷代码时保留原文件的版权头；MPL 文件拷过来仍是 MPL；在 `THIRD_PARTY_NOTICES.md` 登记来源 |
| 🟡 **有条件** | LGPL-2.1 / LGPL-3.0 | 只能作为动态链接库或可替换组件使用，不改源码，或者修改部分单独开源。iOS 上动态链接受限，用之前单独评审 |
| 🔒 **只参考** | GPL-2.0、GPL-3.0、AGPL-3.0 | 可以读代码、看它怎么实现、实现同样的公开协议和文件格式；**不复制代码，也不逐行翻译成另一种语言**（翻译也算衍生作品）。如果某个 GPL 组件特别有价值，可以评估做成用户自己另外安装的可选组件，不随应用分发，单独评审 |
| ❌ **不碰** | 非商用条款（CC BY-NC、MusicFree 的附加条款）、PolyForm Strict、专有 EULA | 连"参考实现"也尽量避免，只看公开的产品形态 |

### 4. 协议、格式、数据不受代码许可证限制

下面这些可以直接实现或使用，和提供它们的项目用什么许可证无关：

- 公开的 API 规范：OpenSubsonic、Jellyfin API、Plex API、LRCLIB API、MusicBrainz API
- 文件和数据格式：LRC、增强 LRC、TTML 歌词、ID3v2、Vorbis Comment、APE 标签、M3U/PLS
- 开放数据：MusicBrainz 核心数据（CC0）、AutoEq 的耳机数据（MIT）
- 标签字段映射：参考 MusicBrainz Picard 的公开文档，自己写映射表

注意：要遵守各服务自己的使用条款（限速、User-Agent、商用许可），这一条在 REQUIREMENTS 第 5 节里另有约束。

### 5. 对 AI agent 的要求

agent 从外部项目拷代码或照着改写时，必须在提交说明里写清楚**来源仓库、文件路径、许可证**。🔒 和 ❌ 档的项目，agent 不能打开源码文件当模板改写，只能看文档、README 和实际运行效果。

## 备选方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| **MPL-2.0（采纳）** | 能上商店、能做 Pro、能复用 MPL 代码；改动核心的人必须回馈 | 不能直接拷 GPL/AGPL 代码 |
| GPL-3.0 | 能直接拷 Navidrome、Feishin 等 GPL 代码 | 上不了 App Store，做不了闭源 Pro；而且这些项目大多是 Go、TypeScript、C#，语言不同，能直接拷的部分本来就很少 |
| Apache-2.0 / MIT | 最宽松 | 别人可以拿核心去做闭源产品，不用回馈 |

## 后果

- `core/deny.toml` 的许可证白名单已经和 ✅ 档一致，不用改；LGPL 继续单独评审。
- 需要补：根目录 `LICENSE`（MPL-2.0 全文）、`THIRD_PARTY_NOTICES.md`、每个源文件的 MPL 文件头（可以用脚本批量加）。
- 接受外部贡献时不需要 CLA：Pro 代码在单独的仓库，不依赖重新授权开源部分。
- 以后如果想换成 GPL，从 MPL-2.0 换过去是兼容的（MPL-2.0 第 3.3 节）；反过来就很难。
