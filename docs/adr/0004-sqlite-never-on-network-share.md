# ADR-0004：SQLite 绝不放在网络共享上；共享数据用"每设备独占写"的分片文件

- 状态：已采纳
- 日期：2026-11-19
- 相关需求：LIB-05、SYN-02

## 背景

多台设备要共享扫描索引和同步数据，最省事的做法是把 SQLite 放到 NAS 上。但 SMB / NFS 上的文件锁不可靠，SQLite 官方明确不建议这样做，多个客户端同时写会损坏数据库。

## 决策

- 主数据库永远在本机。
- NAS 上的共享数据（`.lekis/index/`、`.lekis/sync/`）使用**不可变的分片文件**（`cbor + zstd`）：
  - 共享索引按目录分片，写入时先写临时文件再重命名；
  - 同步日志每台设备只写自己的子目录，只追加不修改。
- 读取方负责合并；任何文件损坏都只影响那一个分片，可以重建。

## 后果

- 需要实现分片格式的版本号和兼容处理（文件头带格式版本）。
- 需要定期压缩旧日志（生成快照）。
